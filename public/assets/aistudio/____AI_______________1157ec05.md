# ローカルAI基盤 学校書類管理・検索システム 仕様書

## 1. システム概要
* **システム名称**: ローカルAI基盤 学校書類管理・検索システム（仮称）
* **キャッチコピー**: セキュリティと効率化を両立する、ローカルAI基盤の学校書類管理システム
* **主な利用者**: 小・中・高校の教職員および学校事務職員
* **主要目的**: 
  * 個人情報や機密情報を含む学校書類を外部クラウドへ送信せず、完全に校内ローカル環境で保管・蓄積する。
  * ローカルVLM（視覚言語モデル）およびローカルLLMを用いた高精度検索・要約により、過去資料やマニュアルを瞬時に抽出して教員の業務負担を飛躍的に削減する。

---

## 2. システムアーキテクチャ（動作形態）
本システムは **ハイブリッド型アーキテクチャ** を採用します。

* **校内LANサーバー（メイン環境）**:
  * 校内ネットワーク内の専用PC/サーバー上にAIモデル（LLM/VLM）、ベクトルDB、検索 APIを配置。
  * 教員は各PCのWebブラウザからシステムにアクセスして利用。
* **ローカルクライアント（スタンドアロン対応）**:
  * オフライン環境や出張時、ネットワーク障害時にも利用できるよう、個人の端末内のみで動作する軽量クライアントパッケージを用意。

## 3. AI ＆ データ処理パイプライン仕様

### 3.1 AI-OCR ＆ ドキュメント解析（ローカルVLM）
* **採用モデル**: ローカル視覚言語モデル（Qwen-VL / Llama-Vision等）
* **機能**:
  * 一般的なテキスト文字だけでなく、手書き文字、図表、レイアウト構造を含めて正確にテキスト化・構造化。
  * PDF、各種画像フォーマット（JPG, PNG）、Office文書（Word, Excel, PowerPoint）の直接取り込みに対応。
  * スマホ・タブレット等の端末カメラからの直接撮影取り込み機能を標準搭載。

### 3.2 個人情報・秘匿情報の自動マスク処理（データ匿名化）
* **処理タイミング**: VLMによるテキスト化直後、データベースへの保存前。
* **機能**:
  * 生徒・保護者・教員の氏名、学籍番号、住所、電話番号などを自動検出し、匿名ID（例: `[生徒ID: S-1029]`）へ置換・マスク処理を実施。
  * データベースおよびベクトルDBには仮名化されたテキストのみを保存し、漏洩リスクを根本から排斥。

### 3.3 ローカルLLM ＆ RAG（検索・要約エンジン）
* **LLM実行基盤**: vLLM / LM Studio（GPUリソースを最適化活用）
* **モデル規模**: 14B〜32Bクラスのローカルオープンモデル（日本語対応・高精度対話能力）
* **ベクトルデータベース**: Chroma / FAISS
* **RAG（Retrieval-Augmented Generation）処理**:
  1. ユーザーの自然言語クエリをベクトル化。
  2. Chroma/FAISSから最も関連性の高いドキュメントスニペット（文脈）を高速検索。
  3. 仮名化された文脈をローカルLLMに提示し、安全・正確な回答や要約を生成。

## 4. UI / UX 仕様

### 4.1 メイン画面構成
**「検索ポータル ＋ カテゴリ別フォルダ ＋ サイドバーAIチャット」統合型UI**
* **トップヘッダー**: 高機能検索窓（キーワード検索・自然言語検索対応）。
* **中央エリア**: カテゴリ別フォルダ一覧（「学年経営」「行事マニュアル」「PTA資料」「生徒指導」など）および最近取り込んだ書類カード。
* **右側（またはポップアップ）サイドバー**: AI対話アシスタント画面。文書についての質疑応答や要約生成をチャット形式で実行。

### 4.2 根拠文書プレビュー機能（エビデンス確認）
* **概要**: AIが回答を作成する際、その元となった書類の該当ページおよび該当箇所のハイライト表示を画面上で同時にプレビュー表示。
* **メリット**: ハルシネーション（AIの嘘）を防ぎ、教員が即座に元資料を点検・確認可能。

## 5. セキュリティ・権限管理仕様

### 5.1 アクセス権限管理（タグ・秘匿度別アクセス制御）
* 各文書に対してアップロード時または自動判別で「秘匿度タグ」を設定。
  * **全校共有**: 全教員が検索・閲覧・AI要約可能。
  * **学年・部局限定**: 該当学年・担当部署の教員のみアクセス可能。
  * **機密（個人情報・指導記録等）**: 管理者・指定担当者のみアクセス可能。

### 5.2 オフライン・ゼロトラスト運用
* 外部インターフェースへのデータ送信は完全に遮断（ネットワーク的 isolated 構成）。
* 通信は校内LAN内部（HTTPS）で完結。

## 6. 入出力要件

| 区分 | 項目 | 内容 |
| :--- | :--- | :--- |
| **入力** | スキャン・ファイル | PDF, JPG, PNG, DOCX, XLSX, PPTX |
| | 直接入力 | スマホ/タブレットカメラでの撮影画像、ブラウザ上ドラッグ＆ドロップ |
| | クエリ入力 | キーボードテキスト入力、カテゴリ絞り込みフィルター |
| **出力** | 回答・要約表示 | ブラウザ上でのリッチテキスト表示 ＋ 元文書該当ページのプレビュー |
| | クリップボード連携 | ワンタップで回答テキストをクリップボードにコピー（週報や引継ぎ資料へ即時貼り付け可能） |

---

## 7. 非機能要件

1. **安全性・倫理**
   * 個人情報の仮名化・ID置き換えにより、万が一の物理的データ紛失時でもプライバシーを保護。
2. **応答パフォーマンス**
   * 検索レスポンス: 1秒以内。
   * LLM回答生成: 5〜10秒以内（14B〜32Bモデル、GPU推論最適化）。
3. **操作性（Usability）**
   * マニュアル不要で直感的に操作できるGoogle風UIとAIアシスタントの統合。

## 8. コンテスト（全情コン）応募用紙への反映ガイド

* **①一言キャッチ**: セキュリティと効率化を両立する、ローカルAI基盤の学校書類管理システム
* **④作品の仕組み**:
  * **ペーパーレス化（ローカルVLM）**: 紙書類や各種ファイルを撮影・アップロードし高精度解析。
  * **個人情報保護・匿名化**: 保存前に自動で氏名等をマスク処理。
  * **ローカルDB/RAG蓄積**: Chroma/FAISSに保存。クラウド送信ゼロ。
  * **ローカルLLM検索・要約**: 14B〜32Bモデルが校内知識ベースから安全に情報抽出。根拠ページプレビュー機能付き。
* **⑤使用した主な技術**: ローカルVLM, vLLM/LM Studio (14B-32B LLM), Chroma/FAISS, Webフロントエンド（React等）
* **⑥特に工夫した点**: 完全ローカル構成、根拠プレビュー付き検索UI、自動仮名化による個人情報保護。
